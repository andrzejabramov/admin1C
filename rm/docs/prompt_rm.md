# Промпт для воспроизведения сервиса `rm`

## Задача

Реализовать сервис удаления бэкапов 1С с вертикальной архитектурой (adapters/services/engines), поддержкой фильтрации по дате и защитой от случайного удаления.

## Требования к интерфейсу

- Единая точка входа: `ib1c rm [флаги]`
- Короткие флаги (стандарт Unix):
  - `-I ИБ` — имя информационной базы (алиас `--ib`)
  - `-A` — все ИБ (алиас `--all`)
  - `-t МЕТКА` — точная метка времени (алиасы `--at`, `--timestamp`)
  - `-b ДАТА` — старше даты (алиас `--before`)
  - `-a ДАТА` — новее даты (алиас `--after`)
  - `-B ДИАПАЗОН` — диапазон (`НАЧАЛО..КОНЕЦ`, алиас `--between`)
  - `-n` — симуляция (алиасы `--dry`, `--dry-run`)
  - `-c` — подтверждение (алиас `--confirm`)
- Справка на русском языке с метками `ИБ`, `МЕТКА`, `ДАТА`, `ДИАПАЗОН`
- Примеры в справке только с тестовыми ИБ (`test_db`, `db_test`)

## Алгоритм работы

1. **Адаптер** (`rm_adapter.py`):

   - Парсит аргументы через `argparse`
   - Валидирует конфликты флагов (`-t` несовместим с `-b`/`-a`/`-B`)
   - Преобразует даты через `core.utils.parse_*`
   - Вызывает методы `RmService`

2. **Сервис** (`rm_service.py`):

   - `remove_backup(ib_name, timestamp=None, after=None, before=None, dry_run=False, confirm=False)`:
     - Валидирует существование ИБ
     - Проверяет безопасность: если нет фильтров + не симуляция + нет подтверждения → отказ
     - Формирует аргументы для `rm.sh`
     - Вызывает `core.engine.run_engine("rm/engines/rm.sh", args, user="usr1cv8")`
   - `remove_all_ibs(dry_run=False, confirm=False)`:
     - Требует явного подтверждения для глобальных операций
     - Вызывает `rm.sh --all`

3. **Движок** (`rm.sh`):
   - Парсит аргументы (`--ib`, `--timestamp`, `--after`, `--before`, `--all`, `--dry-run`, `--confirm`)
   - Защита: реальное удаление требует `--confirm`
   - Фильтрация по дате через сравнение строк (`[[ "$backup_date" > "$AFTER" ]]`)
   - Симуляция: вывод путей без удаления файлов
   - Логирование в `/var/backups/1c/rm.log`

## Критические правила безопасности

1. Удаление без фильтров требует `--confirm` или `--dry-run`
2. Глобальное удаление (`--all`) всегда требует `--confirm` (даже в симуляции для единообразия)
3. Флаги `-A` и `-I` взаимоисключающие
4. Все операции выполняются от пользователя `usr1cv8` (не root)

## Примеры тестовых сценариев

```bash
# Симуляция удаления всех бэкапов ИБ
ib1c rm -I test_db -n

# Удаление бэкапов в диапазоне (требует подтверждения)
ib1c rm -I test_db -a 20260206 -b 20260208 -c

# Глобальная симуляция
ib1c rm -A -n

# Попытка опасной операции без подтверждения → отказ
ib1c rm -I test_db          # ❌ Требуется --confirm
ib1c rm -A                  # ❌ Требуется --confirm
```

## Требования к выводу

- Цветовые коды для статусов (✅/⚠️/❌)
- Структурированный вывод с разделителями
- Для симуляции: префикс `🔍 Симуляция: файлы НЕ будут удалены`
- Для реальных операций: подтверждение `✅ Удалён: /путь/к/бэкапу`
