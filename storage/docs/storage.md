# 💾 Сервис `storage` — спецификация

Сервис `storage` обеспечивает **наблюдаемость** системы резервного копирования 1С: сбор метрик диска, анализ содержимого хранилища, валидацию состояния и управление списком информационных баз. Работает в режиме **только чтение** — не создаёт и не изменяет данные в хранилище.

---

## 🌳 Структура файлов

### Корневые объекты проекта

```
/opt/1cv8/scripts/
├── orchestrator.py          # Единая точка входа (CLI-маршрутизатор)
├── ib_list.conf             # Статический список ИБ для массовых операций
├── .version                 # Версия системы
├── requirements.txt         # Зависимости Python
├── core/                    # Инфраструктурный слой (общий для всех доменов)
│   ├── config.py            # BACKUP_ROOT, load_ib_list(), SSL-параметры
│   ├── engine.py            # run_engine() — универсальный запуск скриптов
│   ├── utils.py             # machine_to_human(), format_bytes()
│   └── exceptions.py        # Кастомные исключения (NotFoundError, RmError)
└── engines/
    ├── utils.sh             # Bash-утилиты (логирование, валидация ИБ)
    └── config/global.sh     # Параметры подключения к БД (PG_HOST, PG_PORT)
```

### Структура домена `storage/`

```
storage/
├── config/storage.sh        # BACKUP_DIR="/var/backups/1c"
│
├── engines/                 # Слой 0: скрипты-движки (bash, прямой доступ к ФС)
│   ├── disk_usage.sh        # Сбор статистики диска через `df` → key=value
│   ├── list_backups.sh      # Поиск файлов бэкапов → TSV (ib_name\ttimestamp\t...)
│   ├── count_backups.sh     # Агрегация количества/размера → TSV
│   ├── validate.sh          # Валидация состояния → ключ=значение + ошибки/предупреждения
│   ├── ssl.sh               # Управление SSL-сертификатами (certbot)
│   └── list_ibs.sh          # [Заглушка] Получение списка ИБ из кластера (не используется)
│
├── services/                # Слой 1: бизнес-логика (чистая, без зависимостей от интерфейсов)
│   └── storage_service.py   # StorageMonitor — агрегация данных из движков
│       ├── __init__()       # Инициализация: загрузка списка ИБ из ib_list.conf
│       ├── _run_engine()    # Универсальный запуск скриптов через core.engine.run_engine()
│       ├── get_disk_usage() | Парсинг вывода disk_usage.sh → dict с конвертацией в ГБ
│       ├── get_backups_list()| Парсинг TSV → list[dict] с Unix timestamps
│       ├── get_stats()      | Парсинг TSV → агрегация по ИБ
│       ├── validate_storage()| Обработка вывода validate.sh → ошибки/предупреждения
│       ├── calculate_growth_rate()| Расчёт темпа роста за N дней
│       └── get_full_report()| Сбор всех метрик в единый отчёт
│
└── adapters/cli/            # Слой 2: адаптеры интерфейсов
    └── storage_adapter.py   # CLI-адаптер (argparse → StorageMonitor → вывод)
        ├── Парсинг аргументов (--ib для фильтрации)
        ├── Вызов сервиса (StorageMonitor.get_full_report())
        └── Форматирование вывода (таблицы диска, статистики по ИБ)
```

## ⚙️ Примеры команд

```bash
# Обзор всего хранилища
ib_1c storage

# Детальная статистика по конкретной ИБ
ib_1c storage --ib artel_2025

# Проверка валидности хранилища (внутренний вызов через StorageMonitor)
ib_1c storage validate
```

## 🔗 Зависимости и алгоритм вызова

### Диаграмма вызовов

```
CLI (ib_1c storage)
    ↓
orchestrator.py → обнаруживает адаптер в storage/adapters/cli/storage_adapter.py
    ↓
storage_adapter.py::main()
    ├── argparse: парсинг --ib
    └── Создание экземпляра StorageMonitor()
            ↓
            StorageMonitor::__init__()
                ├── core.config.load_ib_list() → ib_list.conf
                └── core.config.BACKUP_ROOT → Path("/var/backups/1c")
            ↓
            StorageMonitor::get_full_report(ib_name=None)
                ├── get_disk_usage()
                │   └── _run_engine("storage/engines/disk_usage.sh", ...)
                │       └── core.engine.run_engine(..., user="usr1cv8")
                │           └── subprocess → disk_usage.sh → key=value
                │
                ├── get_backups_list()
                │   └── _run_engine("storage/engines/list_backups.sh", ...)
                │       └── core.engine.run_engine(...)
                │           └── subprocess → list_backups.sh → TSV
                │
                ├── get_stats()
                │   └── _run_engine("storage/engines/count_backups.sh", ...)
                │
                └── validate_storage()
                    └── _run_engine("storage/engines/validate.sh", ...)
            ↓
            storage_adapter.py → форматирование вывода в таблицы
```

### Ключевые контракты между слоями

| Слой               | Ответственность                           | Контракт с нижележащим слоем                                                                      |
| ------------------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **CLI-адаптер**    | Парсинг аргументов, форматирование вывода | Вызывает `StorageMonitor.get_full_report(ib_name)` → возвращает `dict`                            |
| **StorageMonitor** | Агрегация метрик, расчёт темпов роста     | Вызывает `_run_engine(script, args)` → возвращает `str` (сырой вывод скрипта)                     |
| **core.engine**    | Запуск скриптов, обработка ошибок         | Вызывает `subprocess.run([...], user="usr1cv8")` → возвращает `dict` с `stdout/stderr/returncode` |
| **Bash-движки**    | Прямой доступ к ФС, сбор сырых данных     | Выводят данные в машинно-парсимом формате (key=value или TSV)                                     |

## ⚠️ Таблица ошибок и их обработка

| Ошибка                               | Источник                      | Обработка                                         | Пользовательский вывод                                           |
| ------------------------------------ | ----------------------------- | ------------------------------------------------- | ---------------------------------------------------------------- |
| **Скрипт не найден**                 | `core.engine.run_engine()`    | Возврат `dict` с `success=False`, `returncode=-1` | `❌ Скрипт не найден: /путь/к/скрипту`                           |
| **Нет прав на чтение**               | `list_backups.sh` (stat/find) | `set -e` → скрипт завершается с кодом 1           | `RuntimeError` в `_run_engine()` → `❌ Критическая ошибка: ...`  |
| **Некорректный формат TSV**          | `get_backups_list()`          | Пропуск строки через `continue`                   | Тихо игнорируется (логируется в системные логи)                  |
| **ИБ не найдена в хранилище**        | `storage_adapter.py`          | Проверка `if parsed.ib not in all_ibs`            | `❌ ИБ 'имя' не найдена в /var/backups/1c` + список доступных ИБ |
| **Ошибка парсинга даты**             | `machine_to_human()`          | Возврат исходной строки                           | Отображается как есть (без падения)                              |
| **Недостаточно данных для прогноза** | `calculate_growth_rate()`     | Возврат `0.0`                                     | `ℹ️ Недостаточно данных для расчёта темпа роста`                 |
| **Пустой каталог бэкапов**           | `get_stats()`                 | Пропуск ИБ без файлов                             | Не отображается в таблице (фильтрация на уровне адаптера)        |

### Особенности обработки ошибок

1. **Сетевой/дисковый сбой при запуске скрипта** → `RuntimeError` с текстом ошибки из `stderr`
2. **Частичная ошибка валидации** (предупреждения) → отображаются в блоке `⚠️ Диагностика хранилища`, но не прерывают работу
3. **Критические ошибки** (отсутствие `/var/backups/1c`) → немедленный выход с кодом 1 и сообщением об ошибке
4. **Некорректные данные в TSV** → graceful degradation (пропуск строки без падения всего сервиса)

## 🔐 Безопасность и ограничения

- Все скрипты уровня 0 запускаются **только от пользователя `usr1cv8`** через `sudo -u usr1cv8`
- Сервис **не имеет права** на запись в хранилище — только чтение метаданных
- Чувствительные данные (пути к `.pgpass`, SSH-ключи) **не используются** в сервисе `storage`
- Предупреждения о правах (`Нет прав чтения для usr1cv8`) фильтруются из вывода для уменьшения шума
