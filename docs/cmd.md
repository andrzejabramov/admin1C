# Справочник команд ib1c

Полный список команд консольного оркестратора администрирования 1С. Все команды поддерживают флаг `--help` / `-h` для получения детальной справки.

---

## 📦 backup — создание резервных копий ИБ

### Синтаксис

```bash
ib1c backup -f {dump,sql} (-I ИМЯ [ИМЯ ...] | -A) [-n]
```

### Флаги

| Флаг      | Альтернатива    | Описание                                                       |
| --------- | --------------- | -------------------------------------------------------------- |
| `-f dump` | `--format dump` | Формат PostgreSQL Custom (быстрый, сжатый бинарный формат)     |
| `-f sql`  | `--format sql`  | Формат архивированного SQL (текстовый дамп + gzip)             |
| `-I ИМЯ`  | `--ib ИМЯ`      | Имя информационной базы (можно указать несколько через пробел) |
| `-A`      | `--all`         | Бэкап всех ИБ из файла `ib_list.conf`                          |
| `-n`      | `--dry-run`     | Симуляция без реального создания бэкапа                        |

### Что делает

- Запускает `pg_dump` через SSH на сервере БД для указанной ИБ
- Сохраняет бэкап в хранилище (`/var/backups/1c/ИБ/`)
- Имя файла: `ИБ_ГГГГММДД_ЧЧММСС.{dump|sql.gz}`

### Вывод в консоль

```
✅ [backup] test_db → /var/backups/1c/test_db/test_db_20260215_143022.dump (12.4 MB)
```

### Примеры

```bash
# Бэкап одной ИБ в формате dump
ib1c backup -f dump -I test_db

# Бэкап нескольких ИБ
ib1c backup -f dump -I test_db db_test

# Бэкап всех ИБ из списка
ib1c backup -f dump -A

# Симуляция без реального создания
ib1c backup -f dump -A -n
```

## 🪪 lic — мониторинг и управление лицензиями 1С

### Синтаксис

```bash
ib1c lic [-A] [-l НОМЕР] [-m] [-b]
```

### Флаги

| Флаг       | Альтернатива    | Описание                                                           |
| ---------- | --------------- | ------------------------------------------------------------------ |
| `-A`       | `--all`         | Сводная таблица по всем лицензионным блокам                        |
| `-l НОМЕР` | `--block НОМЕР` | Детализация блока по регистрационному номеру (с/без суффикса `G0`) |
| `-m`       | `--monitor`     | Мониторинг текущего использования лицензий                         |
| `-b`       | `--backup`      | Создание архивной копии файлов лицензий                            |

### Что делает

- **Без флагов / `-A`**: Чтение лицензионных файлов через `lmutil` → вывод таблицы с колонками: `Блок`, `Всего`, `Использовано`, `Свободно`, `Истекает`
- **`-l НОМЕР`**: Детальный разбор бинарных данных лицензии (владелец, дата активации, ограничения)
- **`-m`**: Проверка доступности лицензионного сервера + текущая загрузка
- **`-b`**: Копирование файлов `.lic` в архивную директорию с временной меткой

### Вывод в консоль

```
ЛИЦЕНЗИИ 1С (сервер: lic-srv.atotx.ru)
┌──────────────┬───────┬────────────┬─────────┬──────────────┐
│ Блок         │ Всего │ Использов. │ Свободно│ Истекает     │
├──────────────┼───────┼────────────┼─────────┼──────────────┤
│ TRADE_1C     │ 10    │ 7          │ 3       │ 2026-12-31   │
│ BASE_1C      │ 5     │ 5          │ 0 ⚠️    │ 2026-06-15   │
└──────────────┴───────┴────────────┴─────────┴──────────────┘
```

### Примеры

```bash
# Сводка по всем лицензиям
ib1c lic

# Детализация блока по номеру
ib1c lic -l TRADE_1C

# Мониторинг текущего использования
ib1c lic -m

# Создание резервной копии лицензий
ib1c lic -b
```

## 🗑️ rm — удаление бэкапов ИБ

### Синтаксис

```bash
ib1c rm [-I ИБ [ИБ ...]] [-A] [-t МЕТКА] [-b ДАТА] [-a ДАТА] [-B ДИАПАЗОН] [-n] [-c]
```

### Флаги

| Флаг          | Альтернатива                      | Описание                                                                    |
| ------------- | --------------------------------- | --------------------------------------------------------------------------- |
| `-I ИБ`       | `--ib ИБ`                         | Имя ИБ (можно несколько через пробел)                                       |
| `-A`          | `--all`                           | Удалить ВСЕ бэкапы всех ИБ (глобальная операция)                            |
| `-t МЕТКА`    | `--at МЕТКА`, `--timestamp МЕТКА` | Удалить бэкап по точной временной метке (`ГГГГММДД_ЧЧММСС`)                 |
| `-b ДАТА`     | `--before ДАТА`                   | Удалить бэкапы старше даты (`ГГГГММДД` или `дд.мм.гггг`)                    |
| `-a ДАТА`     | `--after ДАТА`                    | Удалить бэкапы новее даты                                                   |
| `-B ДИАПАЗОН` | `--between ДИАПАЗОН`              | Удалить бэкапы в диапазоне (`НАЧАЛО..КОНЕЦ`, например `20260206..20260208`) |
| `-n`          | `--dry`, `--dry-run`              | Симуляция без удаления                                                      |
| `-c`          | `--confirm`                       | Подтверждение для реального удаления                                        |

### Что делает

- Сканирует хранилище бэкапов (`/var/backups/1c/`)
- Фильтрует файлы по критериям (ИБ, дата, временная метка)
- При наличии `-c` — удаляет файлы через `rm -f`
- Без `-c` — только показывает, что будет удалено

### Вывод в консоль (режим симуляции)

```
⏭️  [rm] Симуляция удаления:
   • /var/backups/1c/test_db/test_db_20260206_124957.dump (8.2 MB)
   • /var/backups/1c/test_db/test_db_20260207_091533.dump (8.3 MB)
⚠️  Для реального удаления добавьте флаг --confirm
```

### Вывод в консоль (реальное удаление)

```
✅ [rm] Удалено 2 файла (16.5 MB):
   • test_db_20260206_124957.dump
   • test_db_20260207_091533.dump
```

### Примеры

```bash
# Симуляция удаления ВСЕХ бэкапов ИБ
ib1c rm -I test_db -n

# Удаление конкретного бэкапа по метке
ib1c rm -I test_db -t 20260208_183432 -c

# Удаление бэкапов старше даты
ib1c rm -I test_db -b 20260206 -c

# Удаление бэкапов в диапазоне дат
ib1c rm -I test_db -B 20260206..20260208 -c

# Удаление ВСЕХ бэкапов всех ИБ (осторожно!)
ib1c rm -A -c
```

## 💾 storage — мониторинг хранилища бэкапов

### Синтаксис

```bash
ib1c storage [-I ИБ]
```

### Флаги

| Флаг    | Альтернатива | Описание                                  |
| ------- | ------------ | ----------------------------------------- |
| `-I ИБ` | `--ib ИБ`    | Детальный список бэкапов для указанной ИБ |

### Что делает

- **Без флагов**: Сводная статистика по всему хранилищу — общее количество бэкапов, суммарный размер, свободное место на диске
- **С `-I ИБ`**: Детальный список бэкапов указанной ИБ — временная метка, размер, возраст

### Вывод в консоль (общая статистика)

```
ХРАНИЛИЩЕ БЭКАПОВ (/var/backups/1c)
┌──────────────┬──────────┬──────────┬──────────┐
│ ИБ           │ Бэкапов  │ Размер   │ Последний│
├──────────────┼──────────┼──────────┼──────────┤
│ test_db      │ 5        │ 41.2 MB  │ 15.02.26 │
│ db_test      │ 3        │ 24.8 MB  │ 14.02.26 │
├──────────────┼──────────┼──────────┼──────────┤
│ ИТОГО        │ 8        │ 66.0 MB  │          │
└──────────────┴──────────┴──────────┴──────────┘
Диск: 12.4 GB свободно из 50.0 GB (24.8%)
```

### Вывод в консоль (детальный список для ИБ)

```
БЭКАПЫ test_db:
┌──────────────────────┬──────────┬──────────┐
│ Временная метка      │ Размер   │ Возраст  │
├──────────────────────┼──────────┼──────────┤
│ 20260215_143022.dump │ 12.4 MB  │ 2 мин    │
│ 20260214_091533.dump │ 12.3 MB  │ 1 день   │
│ 20260213_184511.dump │ 12.2 MB  │ 2 дня    │
│ 20260212_112244.dump │ 12.1 MB  │ 3 дня    │
│ 20260211_083015.dump │ 12.0 MB  │ 4 дня    │
└──────────────────────┴──────────┴──────────┘
```

### Примеры

```bash
# Общая статистика хранилища
ib1c storage

# Детальный список бэкапов для ИБ
ib1c storage -I test_db
```

## ⚠️ Важные правила безопасности

| Операция                                   | Требуется флаг `--confirm` | Режим симуляции                      |
| ------------------------------------------ | -------------------------- | ------------------------------------ |
| Удаление бэкапов (`rm`)                    | ✅ Да                      | ✅ `-n` / `--dry-run`                |
| Создание бэкапов (`backup`)                | ❌ Нет                     | ✅ `-n` / `--dry-run`                |
| Резервное копирование лицензий (`lic -b`)  | ❌ Нет                     | ❌ Нет (всегда реальное копирование) |
| Мониторинг (`storage`, `lic -A`, `lic -m`) | ❌ Нет                     | ❌ Нет (только чтение)               |

> 💡 **Правило:** Все деструктивные операции (`rm`, `backup` с реальным созданием) должны сначала проверяться в режиме `--dry-run`.
